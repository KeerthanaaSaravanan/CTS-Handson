# Custom DRF Action: Enrolled Students in a Course

## Endpoint
GET `/api/courses/{id}/students/`

## Purpose
This endpoint returns a list of all students who are enrolled in the specified course. It leverages the relationships between `Course`, `Enrollment`, and `Student` models.

## How It Works
1. The `CourseViewSet` includes a custom action decorated with `@action(detail=True, methods=['get'])`.
2. `detail=True` indicates that the action operates on a single instance (identified by `pk`).
3. The method `students` retrieves the course object using `self.get_object()` (which returns a 404 if not found).
4. It then queries the `Enrollment` model for all records where the `course` matches the current course.
5. From these enrollments, it extracts the related `student` instances.
6. Finally, it serializes the list of students using `StudentSerializer` and returns the response.

## Example Request
```http
GET /api/courses/1/students/
Accept: application/json
```

## Example Response (200 OK)
```json
[
    {
        "id": 1,
        "first_name": "John",
        "last_name": "Doe",
        "email": "john.doe@example.com",
        "department": 1,
        "enrollment_year": 2023
    },
    {
        "id": 2,
        "first_name": "Jane",
        "last_name": "Smith",
        "email": "jane.smith@example.com",
        "department": 1,
        "enrollment_year": 2023
    }
]
```

## Expected Status Codes
- **200 OK**: Successfully retrieved the list of enrolled students.
- **404 Not Found**: If the course with the given ID does not exist.

## Example Requests (using curl)
```bash
# Get students for course with ID 1
curl -X GET http://127.0.0.1:8000/api/courses/1/students/

# If the course does not exist
curl -X GET http://127.0.0.1:8000/api/courses/999/students/
# Returns 404 with error: {"detail": "Not found."}
```

## Notes
- This endpoint is read-only (GET only) as defined by `methods=['get']`.
- The URL is automatically generated by the DRF router because we used a ViewSet and registered it with the router.
- The `detail=True` setting in the `@action` decorator ensures that the URL includes the primary key (`<int:pk>/`) as part of the path.
